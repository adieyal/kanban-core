# Automation

Automation is a small, stable extension point for business reactions inside the
same facade transaction:

```text
event + immutable facts -> supported actions -> normal Kanban business rules
```

Automation proposes actions; it does not mutate the board. Events notify external
consumers about what happened. Automation is business behavior that reacts inside
the current transaction and requests supported Kanban actions.

## Public contract

Implement the runner using only the public SPI:

```python
from kanban.spi import (
    AutomationFacts,
    AutomationRunner,
    MoveCardAction,
)


class TriageRunner:
    def evaluate(self, event, facts: AutomationFacts):
        if event.type != "card.created":
            return ()
        card = facts.card(event.entity_id)
        if card is None or card.archived:
            return ()
        return (MoveCardAction(card.id, "triage"),)
```

`AutomationRunner.evaluate(event, facts)` receives an immutable `Event` and
detached `AutomationFacts`. Facts contain only card and column observations; they
do not expose a board, repository, service, or transaction coordinator.

The only supported action is `MoveCardAction(card_id, to_column_id)`. Kanban Core
executes it through the same move path used by `KanbanFacade`, so target-column
existence, WIP limits, workflow policy, ordering, event generation, optimistic
concurrency, and unit-of-work behavior remain in core.

## Transactions and chaining

Automation runs before the facade operation commits. If a runner returns an
invalid action, the complete facade operation fails and no partial state or event
is committed. Invalid automation is not silently swallowed and automation is not
post-commit best effort.

Events generated by an automated move can trigger further automation. The chain
is synchronous and bounded. `correlation_id` identifies the original facade
operation across the chain, while `causation_id` points to the event that caused
the next automated action. The configured chain limit protects against loops.

Do not define persisted automation rules, custom events, callbacks, generic
commands, mutable aggregate access, or new action types through this contract.
